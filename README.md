# llm-energy-certificates

Artifact for the manuscript *Worst-Case Energy Certificates for LLM-as-a-Service: Which Serving Knobs Back an Energy SLA, and at What Price on Production Traces* (Dat Lam Quoc, FPT School of Business and Technology (FSB), FPT University; submitted to IEEE Transactions on Services Computing, 2026). It asks which serving knobs give a worst-case energy guarantee per request and per SLA window, and what that guarantee costs on production traces. Submission tag: `v1.0.1-tsc-submission` (title change and Fig. 1(b) axis direction; `v1.0.0-tsc-submission` is kept unchanged, and `results/numbers.json` is identical at both tags).

## What the artifact shows

| Claim | Where |
|---|---|
| Closed-form certificate E_max(P_max, M), quadratic in the output cap M (Thm 1) | `code/energy_model.py`, `code/e1_energy_check.py` |
| Certificate price curve on Azure 2023/2024, BurstGPT and Mooncake; prompt-aware output budget M_T(p) vs fixed output cap (Thm 3); SLA-window over-provisioning | `code/certificate_curve.py` |
| Adaptive gates (TALE-like, entropy exit, conformal stop, loop detector) save energy on benign traffic but not in the worst case (Thm 2) | `code/adaptive_vs_cap.py` |
| Continuous batching with a KV budget: attributed-energy amplification Γ under KV reservation, FCFS-priority recompute and size-based preemption, with and without chunked prefill (Thm 4) | `code/batch_kv.py`, `code/e4_summarize.py` |
| Randomised checks of Thm 1–4 (seeds 42–46) | `code/verify_bounds.py` → `results/bounds_check.csv` |
| Laptop measurement of decode energy vs context (llama.cpp, Qwen2.5-1.5B, RAPL) and a controllability probe | `code/e5_laptop.py`, `code/e5_probe.py` |
| Every number printed in the paper | `results/numbers.json` (generated by `code/make_numbers.py`) |

Pre-registered outcomes, reported as registered: H1 pass (vs the context-length baseline), H2 fail in 18/144 cells, H3 pass, H4 borderline pass, **H5 fail** under the registered Thm 4 bounds (0 violations under the corrected bounds), **H6 fail** (laptop net-energy fit R² = 0.43; see `results/e5_laptop_fit.json`), **H7 fail** (no probe prompt passed 20 000 tokens before a simulated gate fired; `results/e5_probe.csv`). The full verdicts are in `results/numbers.json` → `prereg`; the preregistration texts (Vietnamese, verbatim, 16 and 17 October 2026) are in `prereg/`.

## Reproduce

```
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
set THS_DATASETS=D:\Datasets          # raw traces, see DATA_SOURCES.md
cd code
pytest -q tests
python trace_summary.py
python build_energy_params.py
python e1_energy_check.py
python certificate_curve.py --full --n-boot 200
python adaptive_vs_cap.py
python batch_kv.py grid --trace azure2024_conv
python batch_kv.py grid --trace burstgpt
python batch_kv.py livelock
python batch_kv.py livelock --B 64
python e4_summarize.py
python verify_bounds.py                 # seeds 42-46
python make_figures.py
python make_numbers.py
```

The E4 grid takes about 45 min per trace on a 4-core laptop. E5 (`e5_laptop.py run`, `e5_probe.py run`) needs Windows, the GGUF model and `llama-server` listed in `DATA_SOURCES.md`; its outputs are included in `results/`, so `make_numbers.py` runs without it. Heavy scripts stop themselves when free RAM drops below 6 GB (`common.ram_guard`).

## Verify

`MANIFEST_SHA256.txt` lists the SHA-256 of every file at the tag. The manuscript prints the SHA-256 of `results/numbers.json`:

```
5359fd4302633ea3bcd91aeb6b232c6995f3ccf58092888ff51a1a1558c4130a  results/numbers.json
```

`.gitattributes` sets `* -text`, so a checkout on any OS keeps the bytes (and hashes) unchanged. `python code/make_numbers.py` in a fresh venv regenerates `results/numbers.json` with identical values for every key.
